# MVP 验收原则与场景草案

版本 0.3；2026-10-14，按会议及用户整理文字 MN01 更新，待业务与技术评审。下列是验收草案，本轮无业务代码，未执行这些业务测试。首批方案相关部门试点，验收人待 D101 指定；每日/提前一天、未申请或被拒警示、未评价零分等已有口径，日历、时刻、角色/数据范围及评分完整规则不发明默认值。

## 场景清单

| 用例 | 前提与动作 | 预期结果 | 关联 |
| --- | --- | --- | --- |
| A01 项目与任务 | 有权 PM 建试点项目、节点和任务，分派负责人并设期限/交付标准 | 记录可检索且范围正确；缺必填项不能产生半条有效任务 | M01、M02 |
| A02 完成与退回 | 执行者提交成果，有权人员按 D103 验收或退回 | 区分报告与确认；保留成果、意见与状态历史；无权人员不能确认完成 | M02、M03 |
| A03 试点项目总览 | 两项任务分别进行中与阻塞，更新项目情况 | 总览反映真实记录、待协调事项与更新时间；未定义算法时不编造进度百分比 | M01、M06 |
| A04 多轮方案反馈 | 初版提交，登记甲方意见，提交修订版，再内部复核 | 两版及各自反馈时间/来源均可追溯；旧版不被覆盖，当前采用版有明确依据 | M03 |
| A05 等待与改期 | 员工报告等待甲方并提出新日期 | 记录为员工报告；是否停钟按 D106，原期限保留；未授权或未批准改期不生效 | M02–M05 |
| A06 提醒边界 | D105 补齐日历/时刻后，覆盖每日提醒、到期前一天预警的触发点前/当时/之后，并重复调度 | 符合条件才提醒；同一业务事件不重复创建通知；关闭后不继续催办；不能为提前预警静默提前正式截止日期 | M04、E17 |
| A07 通知异常 | 模拟接口拒绝、超时、重复回调、发送结果未知、重启恢复 | 记录失败/未知，按策略重试或待核查；业务状态不重复变更，不误标送达或阅读 | M04、M07、M08 |
| A08 升级与解除 | D105 明确共同提醒和逐级升级适用事件后，构造逾期/无反馈/严重异常及普通阻塞 | 仅符合条件才发给指定人员；不硬编码所有事件先 PM 后高层；保留规则版本、证据和处理记录，可按权限纠错/关闭 | M05、E17 |
| A09 越权防护 | 成员篡改用户/项目/任务 ID，查询其他项目、统计、文件或摘要 | 服务端拒绝未授权访问，响应不泄露内容；配置管理员也不能超出业务授权 | M01–M08 |
| A10 并发与重复 | 同一任务同时改期/验收；重复提交相同请求 | 按明确冲突规则处理，避免覆盖已确认状态；审计能重建关键变更 | M02、M08 |
| A11 总裁摘要 | 授权范围中存在延期、未更新及正常项目 | 数字与任务数据一致，结论有来源/时间/范围；无资料标未知，不凭无回复断言怠工 | M06 |
| A12 AI 条件验收 | D108、D110 批准后，测试无证据问题、越权提问及恶意文本指令 | 只读取获授权数据，不编造事实、不执行文本中的改期/提权命令；无法判断明确说明 | M06，仅启用 AI 时 |
| A13 企微实测 | D109 授权后，用测试角色打开消息入口、登录并反馈；另测伪造回调 | 身份与任务授权正确，反馈只入库一次；伪造/无效事件被拒绝；真实客户端路径可操作 | M07、M08 |
| A14 群信息来源 | D114 核准路径后，将一条授权的项目消息/提交记录关联成果和节点，模拟重复接收 | 项目、来源、时间及证据可定位；不重复建记录；不能将未授权群的信息自动吸纳 | M09 |
| A15 定向与核心汇总 | 核心管理人员、项目成员、不同专业人员分别查看同一项目的通知/汇总；再改变授权关系 | 只取得获授权内容；摘要、附件、旧链接与 AI 不绕过权限；不把入群等同于全部授权 | M08、M09 |
| A16 群能力不足 | 所选接口无法读取普通群、群关联失效或消息失败 | 明确标识不可用/未同步；只有 D114 接受后才采用备用路径；不伪造“已同步” | M07、M09 |
| A17 人工节点质量评价 | 有权评定者对指定成果版本给出结论/意见；尝试无权评分、改分和重复评价 | 评价者、对象版本、意见与修改可追溯；未评单独表示；不能擅自补齐分值映射或自动生成绩效排名；计分语义另见 A23 | M03、M10、E19 |
| A18 业务与技术过程 | 业务方给期限和要求，技术人员反馈问题，负责人提出质量意见，管理层查询未完成原因 | 展示当时要求、版本、反馈和变更链；区分事实与未核实报告；不凭 AI 自动定责 | M02、M06 |
| A19 甲方修改与节点 | 原方案提交后登记新的甲方修改，建立跟进节点并关联原项目/成果 | 原记录仍可查，新要求与负责人可定位；不得把每次修改当成无关联的新项目 | M02、M03 |
| A20 改期例外 | 需要改期时分别构造未申请、待审批、被拒、获批；按 D106 补齐的时点触发提醒 | 未申请/被拒仍警示；待审批行为与停钟按 D106；无获批新期限不静默覆盖原期限；处理全过程可查 | M02、M04、M05、E18 |
| A21 核心管理提醒 | D105 指定某事件共同通知项目经理与高层；另有不在名单的人员 | 按事件名单通知，既不漏掉指定接收人，也不向未授权者广播；共同通知不被 PM 待处理状态无故阻断；重复/解除按规则 | M04、M05、E17 |
| A22 全面查看与写入边界 | D104 明确“全部”的项目范围后，项目经理、上级管理者和技术人员分别查看范围内外项目，再尝试无权改期/验收 | 全面查看覆盖获批范围，专业人员按规则查看；文件/导出与 AI 同样核验；可查看不自动获得改期/验收权 | M08、E16 |
| A23 未评价与零分 | 在 D113 确认启用计分后，对比未评价节点、已评良好 0 分节点及获批正负分节点；尝试清空评价 | 未评价贡献 0、不奖不扣，状态与已评价 0 分清楚区分；不因零分判定已完成；正负分只按完整获批表处理；删改保留依据和历史 | M10、E19 |

通知去重的内部目标是同一逻辑事件不重复处理；外部发送在超时后结果未知时不能凭空保证端到端“恰好一次”。需在方案中定义核查、重试和重复风险处理，并在验收记录中说明可验证边界。

## 验收层次

1. 业务规则测试：完成/退回、改期、外部等待、工作日与阈值边界。
2. 集成测试：身份、权限、审计、持久化一致性、重复事件和通知失败恢复。
3. Playwright E2E：员工反馈、PM 验收、跨项目拒绝、管理摘要取证；本地浏览器结果不替代企微真实客户端测试。
4. 业务 UAT：先由方案试点部门的业务/经营、技术和管理人员核对术语、证据、群协同与管理介入；咨询及更多部门流程留到扩展阶段，不再作为首轮并行前提。
5. 生产门槛：数据政策、运行与恢复责任、发布授权分别审查；UAT 通过不自动授权上线。

## 指标提案

首轮记录任务关键字段完整性、实际触发/发送延迟、重复事件、误报、PM 催办与汇总耗时、摘要事实可回溯情况。确定样本、分母、测量窗口及基线后，由 D112 批准目标；不沿用 R2 中 95% 或固定周数作为承诺。

会议强化“管理层能调取过程，知道哪个节点、要求、变更或质量反馈出了问题”。增加抽查过程证据完整性和人工质量评价可追溯性；数值目标仍待定。A14–A17、A21–A23 涉及群路径、评价范围或配置细则，依对应决策定案后执行，不能声称这些能力或测试已经完成。

权限拒绝、事实准确与变更可追溯是必须验证的质量条件；通过已知用例不等于保证不存在未知缺陷。测试报告至少记录用例、环境、虚构/脱敏数据来源、配置版本、结果、证据和未覆盖事项。不得把真实敏感内容写入可公开的测试截图与日志。
