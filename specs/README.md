# 功能规格目录

当前没有已批准的功能规格或实现任务。本目录于 2026-10-09 为开发准备建立，仅提供说明。

后续使用已安装的 Spec Kit 按顺序编号创建功能目录，例如首个编号由工具扫描现有目录后确定，不在这里预占。每个功能的 `spec.md` 记录业务要求，`plan.md` 记录经评审技术方案，`tasks.md` 记录实施任务；其他设计与检查材料由对应步骤生成。

输入从 `docs/discovery/requirements.md`、`docs/product/mvp-scope.md`、`docs/decisions/decision-log.md` 和 `docs/quality/acceptance.md` 取得。只有原始业务目标与得到明确确认的细则可以进入批准基线；参考 `docs/plan.docx` 不是本目录的技术计划。

2026-10-14 会议与文字复核依据为 `docs/meetings/2026-10-14/review.md`、`text-comparison.md` 及决策日志 v0.3。首个规格按方案部门先试编写，覆盖已明确的全面查看方向、每日/提前一天、未申请或被拒警示、未评价零分等；仅将查看范围、时刻/内容、完整评分表等剩余细则列为待决。群接口可行性和外部数据处理仍未定，不把初步方案当作批准的实现设计。

本次仅更新来源和准备状态，没有执行 Spec Kit 生成步骤。可以从 `$speckit-constitution`、`$speckit-specify` 开始文档流程；`$speckit-tasks` 需要先有当前功能的 `spec.md` 和技术 `plan.md`，不是启动项目的第一步。

在用户明确授权前，不运行 implement、不生成业务代码。准备流程见 `docs/development/spec-kit-next-steps.md`。
